// how it works

It counts the work nobody used.

xray reads the spans of each trace, matches every call to the work it caused downstream, and checks who was still waiting for the answer.

01 · MEASURE

Amplification and goodput

How many calls one user request causes, and how much of a callee's running time the caller actually used.

02 · DETECT

Zombie work

Work that kept running after its caller gave up, and for how long, all the way down the chain.

03 · FIX

The missing guard

Every finding names its fix: a retry budget, backoff, or sending the caller's remaining time downstream.

// bring your own traces

Export them with the Collector.

Every service needs OpenTelemetry tracing with context propagation, so a call from one service and the work it causes in the next end up in the same trace. Then write the traces to a file with the OpenTelemetry Collector's file exporter.

Supported: OTLP/JSON (one export request per line, or one document), the OpenTelemetry Python SDK's span JSON, Zipkin v2 JSON (an array of spans), and Jaeger Trace JSON (the file the Jaeger UI's JSON download writes). Optional: if a service queues requests before running them, set the span attribute app.queue_wait_ms on its server span, so waiting is not counted as work.

exporters:
  file:
    path: /data/otlp-traces.json
service:
  pipelines:
    traces:
      receivers: [otlp]
      exporters: [file]
